# Серверная приёмка SSO — 30.10.2026

Сквозной вход установлен для `https://platforma.bravo-soft.ru`. Реальная проверка
выполнена в согласованной компании `24`, регистрация `465304`, каталог
`https://cabinet-05.kodeks.expert`. Существующие пользователи и кабинеты не менялись.

## Что установлено

- Auth API: выдача одноразового тикета, проверка подготовленной пользовательской
  сессии, погашение тикета и установка cookies на домене выбранного каталога.
- Backend ИТРХаб: `POST /api/expert/sso-link`; компания, reg и пользователь берутся
  из текущей авторизации и БД, браузер передаёт только постоянную ссылку кабинета.
- Frontend ИТРХаб: свежая ссылка при нажатии на кабинет в дереве и боковой панели.
  Одноразовый адрес не сохраняется в структуре компании.
- Nginx: отдельный `/sso` в HTTPS-блоках `cabinet-02..07.kodeks.expert`.
  Дополнительный nginx на сервере служб Кодекса не потребовался.

Исходники и сборки SSO опубликованы в `release`: `61edfbe`, `7b38379`, `4d2a2de`.
Исправление подтверждённого ID группы и очистки: `0f18e29`.
Production backend и frontend ИТРХаб собраны и запущены; Auth API и worker
пересобраны и обновлены. Использован закешированный Node base image по digest:
обычный запрос mutable tag получил Docker Hub 429. Исходные Dockerfile портала
ради этого не менялись; отдельные build-файлы сохранены в закрытой резервной копии.

## Реальная браузерная проверка

Итоговый прогон: `sso_accept_6d8bca7f5936`, отчёт `sso_probe_final.json`, `ok=true`.

1. Проверены исходные группы, кабинеты, форма прав, активная компания и реальные
   значения enum в БД портала.
2. Созданы временные группа, пользователь Кодекса и отдельный скрытый кабинет;
   кабинету назначены права только на тестовую группу.
3. Созданы временная учётная запись портала и её связь с компанией `24`.
4. Чистый Chromium, без cookies каталога, выполнил вход через форму ИТРХаб
   (`mode=UI`). JWT сверён с ID тестовой связи, компанией и ролью.
5. Из страницы портала вызван его настоящий `/api/expert/sso-link` с текущей
   авторизацией. Полученная одноразовая ссылка открыта в новой вкладке.
6. Браузер дошёл до тестового кабинета с HTTP 200, без формы входа Кодекса.
   Пользовательский GraphQL подтвердил видимость именно тестового кабинета.
   Cookie `Auth` принадлежит тестовому пользователю и домену `cabinet-05`, имеет
   Secure/HttpOnly и не содержит ошибочных кавычек вокруг base64.
7. Повторный тикет отклонён: HTTP 401, `SSO_TICKET_INVALID`.
8. Запрос ссылки на другой каталог (`cabinet-04`) отклонён порталом: HTTP 403.

Это реальная проверка входа через UI портала и перехода по его API, а не mock.
Нажатие существующего узла дерева отдельно не воспроизводилось: его обработчики
проверены тестами и production-сборкой; тестовый кабинет в дерево компании не
добавлялся. Сценарий самодостаточен в `scripts/sso_server_probe.py`.

## Очистка

Все восемь проверок очистки итогового прогона прошли:

- сняты тестовые права и удалён тестовый кабинет;
- удалены пользователь и группа Кодекса;
- удалено владение группами тестового пользователя в БД интеграции;
- удалены тестовая связь с компанией и пользователь портала;
- группы, кабинеты и форма прав совпали с исходным снимком.

Первый прогон также подтвердил вход, но остановил удаление группы из-за неверной
проверки поля ID в тестовом скрипте. Реальная форма содержит `grp=<id>`, `gn` пустой.
Оставшаяся группа была удалена по проверенной полной форме; другие группы
сохранены. После исправления выполнен новый полный прогон, приведённый выше.

После проверки приватный профиль с временными паролями удалён на хосте и в
контейнере. Отдельный запрос подтвердил отсутствие обеих тестовых учётных записей
портала.
