# Речь: состояние интеграции с Кодексом (~4 мин)

**Легенда:** `/` — короткий вдох (полсекунды) · `//` — пауза в секунду · `⏸ ————` — большая пауза 2–3 сек: глаза в зал, только потом дальше. Одна строка = одна мысль, конец строки = микро-остановка.

---

Коротко / о текущем состоянии интеграции с Кодексом. //

⏸ ————————————————

Мы собрали и запустили рабочий бэкенд / между **ИТРХАБ** и сервисами Кодекс. //
Модуль развёрнут / и **уже работает на реальном примере**. //

Реализованы авторизация / и автоматическое создание компаний, / подразделений / и пользователей. //
Боевой пример: / структура компании из **32 отделов** — / создана примерно **за пять минут**, / вместе с распределением прав. //

⏸ ————————————————

Готова и новая функция — / **уточнение кабинета клиента**. //
Клиент получает полный кабинет, / заполняет опросник, // и система определяет, / какие разделы ему нужны, / а какие можно убрать. //
Интеграция сшита от ИТРХАБ до кабинета: / фронт передаёт корректные данные, / запросы принимаются и обрабатываются. //

Сейчас уточнение работает в **безопасном режиме**: //
система формирует план изменений / и записывает его в журнал, // но пока / ничего не удаляет. //
Это осознанное решение — / удаление в кабинете **необратимо**. //
Поэтому сначала сверяем план, / потом включаем боевой режим. //
На живых запросах мы нашли три ошибки — // все три исправлены, / большая часть уже на проде. //

⏸ ———————————————— *(смена акта — не спеши)*

Второй модуль — / **конструктор кабинетов**. //
Раньше целевой кабинет собирался по ТЗ вручную — / это часы работы / и человеческий фактор. //
Теперь конвейер делает это сам. //
Загружаем Excel-ТЗ, / система разбирает его в дерево кабинетов, / находит на службе нужные списки — //
сопоставление умное: / понимает морфологию, / опечатки / и разночтения в названиях, — //
создаёт каскад кабинетов, / наполняет виджеты / и **сама себя проверяет**: //
читает созданное обратно через API / и сверяет каждый список. //
Главный принцип — / **ничего не создаём вслепую**: //
если список не сопоставился однозначно — / публикация останавливается, / с отчётом, где именно проблема. //
Управление — через веб-панель: / выбрал службу, / загрузил ТЗ, / видишь прогресс по стадиям / и ссылки на готовые кабинеты. //
Итог: / кабинет по ТЗ собирается **за минуты** / вместо часов. //

⏸ ————————————————

Фундаментом для конструктора стал / **единый реестр списков КО**. //
Выяснилось: / у каждой из шести служб Кодекса — / собственные списки и идентификаторы, // хотя состав должен быть единым. //
Реестр построен на актуальной пользовательской базе: //
хранит эталонный состав КО / и отдельно отслеживает состояние каждой службы. //
В интерфейсе теперь видно: / сколько списков реально есть на службе, / какие актуальны, / у каких изменился состав, / и какие ещё не сопоставлены. //
Четвёртая служба уже прошла полную сверку: //
каталог читается без ошибок, / существующие списки больше не считаются отсутствующими, / дубли вслепую не создаются. //
Параллельно с контентом провели сверку наименований: //
нашли и исправили опечатки в папках пользователей / и договорились о едином правиле — //
в ТЗ — полные названия видов продукции, / опросники остаются на коротких. //
Это убирает главный источник ошибок сопоставления. //

⏸ ———————————————— *(финишная прямая — сбавь темп ещё)*

Что осталось. //
**Первое** — / выкатить последний фикс, / провести финальный тест уточнения — / и снимаем безопасный режим. //
**Второе** — / подключить сквозной вход из ИТРХАБ в кабинеты: / основной вариант готов к передаче фронту, // резервный — / шлюз на nginx с одноразовыми тикетами. //
**Третье** — / прогнать сверку по остальным пяти службам, / актуализировать изменившиеся списки / и настроить досоздание действительно недостающих КО. //

⏸ ————————————————

Итог. //
У нас три рабочих продукта: / интеграционный бэкенд ИТРХАБ–Кодекс, / уточнение кабинетов, / и конструктор кабинетов с единым реестром КО. //
Система работает / **на реальном примере**. //
Мы уже не на этапе разработки с нуля — //
мы на этапе финальной проверки, / актуализации данных / и поэтапного включения функций в боевой режим. //

Готов ответить на вопросы.

## Опорные цифры (если собьёшься)

- **32 отдела / ~5 минут** — боевой провижининг компании
- **3 ошибки найдены — 3 исправлены** (большая часть на проде)
- **6 служб, четвёртая сверена полностью**
- **Минуты вместо часов** — сборка кабинета по ТЗ
- **2 варианта SSO** — основной + резервный (nginx, одноразовые тикеты)

## Шпаргалка к вопросам

| Вопрос | Ответ |
|---|---|
| Почему юзер не создался? | Воркер ходил за куками сам в себя (127.0.0.1 в контейнере). Починено — ходит по имени сервиса. Проверяем переотправкой. |
| Почему уточнение ничего не удалило? | Безопасный режим (осознанно) + первые запросы фронта были с пустой ссылкой. Данные поправлены, код готов. |
| А если придёт мусор? | DLQ с кодом причины. Ничего не падает и не удаляется вслепую. |
| Удалили лишнее — откат? | Перед изменением читаем полный конфиг кабинета, он в логах — восстановимо. Автобэкап — в бэклоге. |
| Виджет есть, а в справочнике нет? | Не трогаем. Удаляем только известное и невыбранное. |
| Нагрузка? | Последовательная обработка: компания на 32 отдела ~5 мин. Для текущего потока ок, при росте — параллелим по партициям Kafka. |
| Почему нельзя куки на фронт? | Политика браузеров: куки домена ставит только сам домен. Решение — вход через домен кабинета (форма / SSO-шлюз). |

## Приёмы подачи

1. На каждой ⏸ — глаза в зал. Пауза кажется тебе вечностью, залу — нормальным темпом.
2. Жирные слова — с нажимом и чуть медленнее: это якоря.
3. Перед цифрами — микро-пауза `/`: цифра после паузы запоминается вдвое лучше.
4. Паузы-⏸ перед «Второй модуль» и «Что осталось» — смены актов, дай слушателям переварить.
