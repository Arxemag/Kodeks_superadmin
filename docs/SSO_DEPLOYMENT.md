# Сквозной вход из ИТРХаб

Портал: `https://platforma.bravo-soft.ru`. Целевой каталог всегда определяется через `reg_services`, например `465304 → https://cabinet-05.kodeks.expert`. Портал не является общим адресом каталогов.

Установлено и проверено на сервере 30.10.2026: [результаты реального входа и очистки](SSO_ACCEPTANCE_2026-10-30.md).

## Схема

1. Пользователь входит в ИТРХаб. Backend портала получает или формирует его cookie `Auth`.
2. При нажатии на кабинет backend портала вызывает `POST /api/expert/sso-ticket` с `X-Api-Token` и `{reg, uid, path, cookies}`. `reg` и `uid` определяются по текущему пользователю и компании. API проверяет сессию в нужном каталоге.
3. Backend возвращает браузеру одноразовый URL `https://cabinet-0X.kodeks.expert/sso?ticket=...`. Такие ссылки нельзя сохранять в структуре компании или кешировать между нажатиями.
4. Браузер открывает URL верхнего уровня. Nginx соответствующего домена проксирует `/sso` в Auth API с исходным `Host`. API атомарно погашает тикет, устанавливает host-only cookies и отвечает 302 на сохранённый путь кабинета.

Без `cookies` API умеет самостоятельно подготовить подтверждённую сессию пользователя. Повторный ввод пароля в браузере не требуется. Отсутствующий пользователь, пустой пароль, чужой профиль и неуспешный вход не подменяются администратором.

На проверенном production-коде портала `Auth` формируется в `TokensService`; отдельный Kafka-топик входа не обнаружен. Подготовленная сессия может поступать backend портала и другим транспортом: установка cookies в браузере всё равно выполняется через `/sso` на целевом домене.

## Nginx

На `45.10.41.70` nginx уже принимает HTTPS для `cabinet-02..07.kodeks.expert`, затем проксирует обычные запросы на `82.148.21.243:7020..7070`. Устанавливать ещё один nginx на машине служб Кодекса не требуется. Используется отдельный snippet [kodeks-sso.conf](../deploy/nginx/kodeks-sso.conf).

Установщик меняет только подключение snippet в HTTPS-блоках выбранных сайтов. Существующие upstream, сертификаты и HTTP-редиректы сохраняются. Сначала выполнить план и проверку, затем установку с новым каталогом резервных копий:

```bash
python3 scripts/install_sso_nginx.py
python3 scripts/install_sso_nginx.py --apply --backup-dir /absolute/new/backup/nginx
```

Перед записью и после неё выполняется `nginx -t`. При ошибке записи, проверки или reload установщик восстанавливает исходные файлы. Новые сайты подключаются этим же snippet; соответствующий `base_url` добавляется в `reg_services`. Имена шести текущих сайтов являются лишь значением по умолчанию установщика, а не ограничением SSO API.

TLS и домен ответа определяют область cookies; `proxy_pass` сохраняет исходный запрос к шлюзу. Официальные справочники: [nginx proxy module](https://nginx.org/en/docs/http/ngx_http_proxy_module.html), [Set-Cookie](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Set-Cookie).

## Настройки

В `.env` Auth API: `SSO_ENABLED=true`, непустой `SSO_API_TOKEN`, `SSO_TICKET_TTL=60`, `SSO_LOGIN_TIMEOUT=30`, `SSO_COOKIE_HTTPONLY=true`. Токен хранится только на серверах API и backend портала; в frontend-сборку не передаётся.

Тикеты хранятся в памяти одного процесса API. Перезапуск делает неиспользованные ссылки недействительными; пользователь повторяет нажатие. Для нескольких процессов потребуется общее атомарное хранилище. Подготовленная сессия, если передана, проверяется при выдаче тикета и не требует нового логина при переходе.

## Подтверждённый контракт каталога

На `465304` исследован настоящий `authForm` и его обработчик `formSubmit`: он вызывает `/users/login.asp` с `user`, `pass`, `path=/docs`. Завершающий слэш в этом параметре имеет значение: `/docs/` не заменяет `/docs`. Строгий SSO-адаптер распознаёт форму и известный обработчик, требует cookie `Auth` и повторно читает защищённый `/docs/`.

В 20 исследовательских прогонах медиана этапа чтение challenge + вход составила 1439 мс, максимум 2575 мс; получение пароля через администратора в эти замеры не входило. Первая сессия сохранила доступ после последующих входов. Чистый Chromium открыл главную страницу с HttpOnly как включённым, так и выключенным; ошибок JavaScript не обнаружено. Временные пользователи удалены. Это исследование не заменяет итоговый браузерный прогон через установленный `/sso` и кнопку портала.

Итоговая приёмка включает временного пользователя в `465304`, переход через портал в конкретный кабинет в чистом браузере, проверку повторного тикета, другого домена и истечения срока, затем удаление всех тестовых сущностей и сверку исходных настроек.
