## Вывод

Наблюдаемый отказ расположен после публичного nginx, на пути к Кодексу.
Публичные HTTPS-входы, шлюз SSO и readiness Auth API отвечают. Ответ nginx 504
подтверждает, что проблема затрагивает обычный доступ к каталогу, а не только
выдачу одноразовой ссылки.

Прямой TCP timeout с внешней машины сам по себе не доказывает остановку служб:
возможны фильтрация трафика, сетевой сбой или недоступность узла. Состояние
самих процессов Кодекса, актуальный upstream nginx и его error log ещё нужно
проверить изнутри сети.

1. На `45.10.41.70` проверить текущие upstream для шести vhost и сообщения
   `upstream timed out`/`connect() failed`, не выводя URL с действующими тикетами.
2. С этого же сервера проверить TCP и HTTP до `82.148.21.243:7020..7070`.
3. На сервере Кодекса проверить доступность узла, слушающие порты и состояние

4. Восстановить обнаруженную неисправность, затем проверить обычный `/docs/`
   и реальный SSO-переход под согласованной тестовой учётной записью.
